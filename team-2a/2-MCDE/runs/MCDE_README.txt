********************
*** Description *** 
********************

MCDE is a python based post-processing method of Compton-Camera (CC) data generated by Geant4. 
The Geant4 model was developed by Steve Peterson and Jerimy Polf. The primary purpose of the code is to 
add detector timing and trigger effects to the geant4 data to make it more realistic as compared to 
measurements with the PJ3 CC. This document describes the code, required input files and variables, and outputs.

*******************
*** Assumptions ***
*******************

This program assumes several things.
1) The standard PJ3 CC setup, that is 16 modules in 2 planes. 2 modules in X, 4 modules in z.
	This includes the assumption of anode directions of top plane towards the beam, bottom plane away from beam
	(see function calcWeightingPotential)
2) An HDPE target of elemental composition (C2H4)n and ensity 0.97 g/cm^3
3) The proton source is a a Varian ProBeam SC Cyclotron


***************************
*** Required Data files ***
***************************

*** Geant4 csv files *** 
two seperate files, one for "annihiliation" gamma information (essentially 511 keV data)
and one for all other data (non-annihiliation). The file should contain singles, doubles, and triples in one file.
The format for an event should be 

edep1, x1, y1, z1, edep2, x2, y2, z2, edep3, x3, y3, z3

For singles, edep2:z3 should be zerod.
For doubles, edep3:z3 should be zerod.

The easiest way to get these files is by running the two scatterData_root2csv_*.py files included in this directory.
You must edit the two paths to point to the root files, and change the outputs to a reasonable name.

*** Python files ***
There are two primary python files: 
1) detSimFunctRepo.py
	this is the python file that includes all functions that are used in the MCDE model
2) MCDE_Main_Script.py
	This is the primary interaciton/control file used by the model. It allows for changing conrol variables
	that will be explained in a future section.
	

*** Cross Section Data files ***
There are 6 cross section files that must be used. They are for the 6 most likely possible positron emitters present
for a C12(p,x) reaction. The files are loaded in the "count511More" function in the detSimFunctRepo.py file.
Locations of the cross section files should be specified there. By default it assumes the same directory as the .py

	txt_in/C12toB8crossSection.txt
	txt_in/C12toC11crossSection.txt
	txt_in/C12toN12crossSection.txt
	txt_in/C12toC10crossSection.txt
	txt_in/C12toC9crossSection.txt
	txt_in/C12toN13crossSection.txt

*** Pulse shape fitting files ***
These are a set of fitting parameters used when generating induced signal pulse shapes.
There should be 5 files total. The locations are specified in the "moduleSimulation" function
in the detSimFuctRepo.py file. By default it assumes the same directoy as the .py

	txt_in/aList_501x1001.txt
	txt_in/bList_501x1001.txt
	txt_in/cList_501x1001.txt
	txt_in/dList_501x1001.txt
	txt_in/muList_501x1001.txt

*** Required python packages ***
Use pjmc conda environment
	conda activate pjmc_conda

***************************************
*** Variable Declarations and Usage ***
***************************************


The following are variables that should be set in the first part of the main python script file.

beamEne : This is the selected beam energy, [MeV]

simProtons : Total number of source protons used to generate geant data file

DR : does rate [MU/min]

MUdelivered : total number of MU delivered for a real experiement. Note: this value is only used to calculate the
	number of 511 keV gammas to include to ensure the same proportion as the measurements specified by
	MUdelivered/DR. [MU]

useMultiprocessing : (True/False) whether or not multiple threads are spawned to run each module independently.
	if false, all data is processed sequentially by timestamp instead of by module.
	Note: the number of processes is set further down the code. It is currently at 16, which is the number of 	
	modules in PJ3. Additionally, multiprocessing does NOT work if you are trying to get output information
	about inter-module events.

makeEachCrystalAMod : (True/False) Whether or not each crystal is treated as an individual module. If True, the 
	code instead has 64 pseudo-modules. #Do not use with multiprocessing! unless you have some sort of 64 core 	
	computational beast.

simType : a string, e.g." 'ref' ". This is primarily used if saveData is set to true, then it becomes part of the
	saved data file name.

saveData : (True/False) whether or not the data (singles, doubles, triples, timestamps, double-type, triple-type)
	are saved.
 
resTime : aboslute value of active/coinicdence window, in [s]

deadScl : this is a multiplicitive scaling factor for dead time. E.g. a value of 1 = 100%. 0.5 = 50%

rReduction : this is a dividing scaling factor for electron cloud radius. 1 means use full electron cloud. If you want to 
	   effectively disable electron cloud-multipix triggering, divide by 10000 or some other large number. 


********************
*** Loading Data ***
********************

Immediately following the variable declariations is a section where you should load your data. Six variables need to be 
loaded, 3 for non-511 keV data and 3 for 511/annihilation data.The variable names and usage is as follows:

singlesANon511 = getSingles( [insert name or path to non-511 keV csv file] )
doublesANon511 = getDoubles( [insert name or path to non-511 keV csv file] )
triplesANon511 = getTriples( [insert name or path to non-511 keV csv file] )

singlesA511 = getSingles( [insert name or path to 511keV/annihilation csv file] )
doublesA511 = getDoubles( [insert name or path to 511keV/annihilation csv file] )
triplesA511 = getTriples( [insert name or path to 511keV/annihilation csv file] )

Note: To ensure "different" 511 datasets for each run, it's advisable to call
random.shuffle(singlesA511)
random.shuffle(doublesA511)
random.shuffle(triplesA511)
after you load the data. This is not required, just suggested because when selecting 511s, it is not random; it just 
looks at the first N items in the list.


************************
*** Running the code ***
************************

Once the above variables are specified, simply execute the python file. This can be done in the IDE of your 
choice (such as Spyder) or from the command line. 

The code can take a signficant amount of time to run. Increased dose rate reduces runtime.

During the execution, several status messages are printed to the terminal:
Starting pixel indexing
Finished indexing
Determining outs
Finished dealing with outs
Putting variables
Done with put

If multiprocessing is selected, then numbers from 0-15 will be output showing when new threads are started.

***********************************
*** Output Data and Information ***
***********************************

At the end of the run, a slew of information is printed to the terminal. [X] denotes a value. The data is as follows:

It took [X] seconds
	Total execution time

Final pixel coincidence count was: [X]
	This is the number of times two gammas occured during the resTime in a single pixel.

Final missed counts was: [X]
	Total number of times a gamma interacted with a dead module. It does not double/triple count
	
Final count overflow was: [X]
	Total number of times an event with 4 or more interactions was recorded.

Final false double was: [X]
	Number of false double events.

Final false triple was: [X]
	Number of false triples.

Final 2->3 was: [X]
	Number of doubles-to-triples

Total Singles: [X]
	Total number of singles

Total Singles in range: [X]
	Number of singles between 0.05 MeV and 2.7 MeV

Total Doubles: [X]
	total number of intra-module doubles

Total Doubles in range: [X]
	number of doubles with both interactions between 0.05 MeV and 2.7 MeV

Total Triples: [X]
	total number of intra-module triples

Total Triples in range: [X]
	number of triples wiht all 3 interactions between 0.05 MeV and 2.7 MeV

Total Events: [X]
	Total number of intramodule events.

S:D Ratio: [X]
	Ratio of singles/doubles.

S:T Ratio: [X]
	ratio of singles/triples

Percent pix > 3: [X]
	Percent of total events with 4 or more interactions.

***
The following are only valid if useMultiprocessing = False. Additionally if using rReduction=1, then the "apparent"
number of inter-module events will be less than 100% even at essentially 0 dose rate. This is because a "single" could
produce a multi-pixel readout equivelent of a double. The denominator is determined before electron cloud generation
happens, which creates this discrepency. 

Percent inter-module doubles detected: [X]
	Percent of inter-module doubles (2 singles in different modules) that were detected. 

Number inter-module doubles detected: [X]
	Raw number of inter-module doubles that were detected. 

Percent inter-module triples detected: [X]
	Percent of inter-module triples (in 3 modules or 2 modules) that were detected.

Number inter-module triples detected: [X]
	raw number of inter-module triples that were detected.

If useMultiprocess = True the percents will be 0 and the counts will be nan.
***

Lastly
Dead time percentage: [X]
	This is a decimal value specifying the average propotion of time a module was in the dead state.


If saveData = True was selected, data will be saved using the approximate format: 
	np.savetxt('%iGEvent_%iMeV_%ikMUmin_%s_res%s_deadScl%s_singles.txt' % (simProtons/1E9,beamEne,DR/1E3,simType,resTime,deadScl),newSings)


This saves data in the current directory. The data saved is 

newSings (singles; size is total singles x 4)
tS (timestamps of singles, in [s]. length totalSingles)
newDoubs (doubles; size is total doubles x 8)
tD (timestamps of doubles, in [s]. length totalDoubles)
dType (coincidence flag. dType = 0: true coincidence. dType = 1: false coincidence)
newTrips (triples; size is total triples x 12)
tT (timestamps for triples; length is total triples)
tType (coincidence flag; 0 = true coinc; 1 = false coinc; 2 = dToT, single is 3rd. 3 = dToT, single is first)

These variables can also be used at will.

NOTE: Unlike in the actual PJ3 system, the newDoubs and newTrips are properly ordered by default.
